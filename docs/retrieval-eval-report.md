# 근거 검색 단계별 평가 기록 — 옥석현 담당

벡터 검색 기준선에서 한 번에 하나씩 바꿀 때마다 같은 평가셋으로 재고, 아래 표에 단계별로 한 줄씩 쌓는다.
원본 결과는 `evals/results/<단계>.json`(로컬, 커밋하지 않음)에 두고 여기에는 지표와 실행 조건만 적는다.
평가셋 규칙은 [evals/retrieval/README.md](../evals/retrieval/README.md)(김지은 담당)를 따른다.

## 3. 재는 법

```bash
.venv/bin/python scripts/run_retrieval_evaluation.py --allow-machine-reviewed \
  --search-callable app.retrieval.common:search --output evals/results/<단계>.json
.venv/bin/python -m evals.retrieval.report evals/results/<단계>.json \
  --previous evals/results/<직전 단계>.json --step <단계> --change "<바꾼 것>"
```

두 번째 명령이 4절과 5절 표에 붙일 줄을 출력한다. 기준선에는 `--previous`를 빼고, `--misses`를 붙이면 Top-1 오답 문항 목록이 나온다(로컬 확인용이라 여기에 붙이지 않는다).
평가셋이 전부 기계 검수라 `--allow-machine-reviewed`가 없으면 채점이 거절된다. 질의당 비용과 채택 칸은 직접 적는다.

### 읽는 법

- K는 부모(도표·결정례·조항) 수다. 청크 순위에서 부모가 처음 나온 순서로 센다. 정답이 거의 1개라 Recall@K와 Hit@K가 같다.
- **단계 비교는 Top-1과 MRR@10으로 한다.** 질문을 원문에서 만들어 낱말이 많이 겹치므로 R@10은 천장에 가깝고, 키워드 검색에 유리한 셋이다. 절대 점수는 실제 카드 질의보다 높게 나올 수 있으니 단계 간 비교로 읽는다.
- **반환 부모 수는 판단 쪽이 실제로 받는 후보 수다.** 도표는 부모당 청크가 7.3개라 청크 10개를 돌려주면 서로 다른 도표가 몇 개 안 될 수 있다. 최소값이 운영 K보다 작으면 검색이 부모별로 묶어 반환하거나 청크를 더 가져온다. 그런 문항의 R@K는 K개보다 적은 후보로 계산된 값이다.
- **직전 대비**는 같은 문항에서 Top-1·상위 5를 새로 맞힌 수(+)와 새로 놓친 수(-)다. 100문항에서 1문항이 1%p라 1~2문항 차이는 읽지 않는다.
- **Top-1 오답**은 1위 부모가 판정 후보 4개 안이면 '판정', 밖이면 '후보 밖'이다. 후보 밖은 라벨 누락일 수 있으니 많아지면 김지은 담당과 함께 사람이 확인한다.
- 조건 구분·예외는 문항이 적어 건수로 본다. 직접 질문이 대부분이라 평균에서는 이 범주의 실패가 보이지 않는다.
- 분할이 `test` 하나라 RRF k·가중치 같은 값을 이 셋으로 고르면 결과가 이 셋에 맞춰진다. 시험한 값과 고른 이유를 6절 메모에 적는다.

## 7. 기록하지 않는 것

- **Recall@20**은 상시 기록하지 않는다. 재순위를 넣을 때 후보를 몇 개 넘길지 정하는 데 한 번 잰다.
- **RAGAS Context Precision·Recall**은 정답 ID로 계산하면 정답이 1개일 때 MRR@K·Recall@K와 같은 값이다. Faithfulness 같은 생성 지표는 판단·질의응답 평가에서 본다.
- **nDCG**는 정답이 1개면 MRR과 같은 정보다.
- **코퍼스·적용판 혼입률과 정답 없음 정확도**는 이 셋에서 재지 않는다. 모든 요청이 `document_id`로 고정되고 `validate_hits`가 다른 코퍼스와 필터 위반을 거절하며, 정답 없는 문항이 0건이다.
