# 검색 평가셋 — 김지은 담당

`*.example.jsonl`은 합성 미라벨 작성 양식이다. 실제 도표·결정례·약관 ID나 정답·평가 성과를 담지 않는다.
`label_status=unlabelled`, `split=unassigned`, 빈 정답 목록을 그대로 채점해서는 안 된다.

- 세 코퍼스 각각 질의·사고 일자·계약 적용판/담보 등 필터·정답 부모 ID·적용판·원문 페이지를 검수한다.
- 양성·검수한 정답 없음·유사 도표 구분·개정 경계·범위 밖·약관 예외 사례를 포함한다.
- 사고 ID 및 동일 원문/개정판 계열을 `split_group_id`로 묶어 train/dev/test 누수를 통제한다.
- 사람 전수 검수는 하지 않는다(11/10 결정). GPT-5가 원문에서 만들고 별도 요청으로 대조한 `machine_reviewed` 정답을 쓰고,
  분할은 평가 전용 `test` 하나로 둔다. 채점은 `scripts/run_retrieval_evaluation.py --allow-machine-reviewed`로 실행한다.
- 지표에는 정답 출처(GPT-5 생성·기계 검수)와 한계를 함께 적는다. 원문에서 만든 질의라 실제 카드 질의보다
  점수가 높게 나올 수 있으므로 검색 방식 간 비교로 해석한다.
- 선택: 여유가 있으면 코퍼스별 10건 표본을 사람이 확인해 오류 건수를 결과에 함께 적는다.
- 도표 Top-1·Recall@3, 인용 ID/페이지 정확도, 코퍼스/적용판 혼입률, p50/p95·비용을 기록한다.
- 벡터 기준선과 구조 필터·Kiwi BM25/trigram·선택적 RRF/재순위를 동일 질의로 비교한다.
- 결과는 무시 경로 `evals/results/`에 저장하고 비식별 지표·실험 조건만 문서화한다.
